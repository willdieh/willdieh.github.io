## Project Layout

Let's take a look at the project layout created by the WebUI template

![WinUI Project Layout](/assets/images/2026-09-14-winrt-2/winui-project-layout.png)

### app.manifest

At the top you'll see the app.manifest. This file will be included along with our .exe to tell windows how to load the application. It allows us to specify several interesting Windows specific configuration settings such as minimum Windows version. We'll just leave it alone for the most part. [Microsoft Documentation here](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests)

**`app.manifest`**
```xml
<?xml version="1.0" encoding="utf-8"?>
<assembly manifestVersion="1.0" xmlns="urn:schemas-microsoft-com:asm.v1">
  <assemblyIdentity version="1.0.0.0" name="WinUIApp.app"/>

  <compatibility xmlns="urn:schemas-microsoft-com:compatibility.v1">
    <application>
      <!-- The ID below informs the system that this application is compatible with OS features first introduced in Windows 10. 
      It is necessary to support features in unpackaged applications, for example the custom titlebar implementation.
      For more info see https://docs.microsoft.com/windows/apps/windows-app-sdk/use-windows-app-sdk-run-time#declare-os-compatibility-in-your-application-manifest -->
      <supportedOS Id="{8e0f7a12-bfb3-4fe8-b9a5-48fd50a15a9a}" />
    </application>
  </compatibility>
  
  <application xmlns="urn:schemas-microsoft-com:asm.v3">
    <windowsSettings>
      <dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">PerMonitorV2</dpiAwareness>
    </windowsSettings>
  </application>
</assembly>
```

An interesting bit of fun can be had here by adding Windows support for UTF-8 as the default character set for the application by adding the following:

`<activeCodePage xmlns="http://schemas.microsoft.com/SMI/2019/WindowsSettings">UTF-8</activeCodePage>`

Unfortunately, WinRT still works in 16-bit Unicode (std::wstring) so it doesn't really help us with our cpp/winrt apps. Might be fun if you're still working in an old win32 app though as in theory at least you could use all the non-wide string functions with standard *char and get free unicode support!

### App.xaml

Next we see the `App.xaml` file and a nested collection of matched `.cpp` / `.h` files. 

These are the main application definition files. I suppose you could say they replace the old `winMain()` function found in win32 apps. 

`App.xaml` contains the actual UI definition in the form of XML based XAML. [Microsoft Documentation here](https://learn.microsoft.com/en-us/windows/apps/develop/platform/xaml/xaml-overview)

**`App.xaml`**
```xaml
<?xml version="1.0" encoding="utf-8"?>
<Application
    x:Class="WinUIApp.App"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:local="using:WinUIApp">
    <Application.Resources>
        <ResourceDictionary>
            <ResourceDictionary.MergedDictionaries>
                <XamlControlsResources xmlns="using:Microsoft.UI.Xaml.Controls" />
                <!-- Other merged dictionaries here -->
            </ResourceDictionary.MergedDictionaries>
            <!-- Other app resources here -->
        </ResourceDictionary>
    </Application.Resources>
</Application>
```

As we begin to build our our application GUI, we'll be adding XAML elements by hand to this file. Unfortunately, in the cpp/winrt workflow, the visual XAML designer that's part of other frameworks just isn't available to us. The best we can do is edit this by hand, probably with sample XML from the [WinUI Gallery](https://github.com/microsoft/WinUI-Gallery). Things like a menu bar, menu items, keyboard shortcuts, etc will go here. 

Perhaps most importantly, we will need a way to display content in the UI that is bound to our C++ code. The XAML definition will use the `bind` keyword to bind UI elements to our variables in C++. Because XAML and cpp/winrt live in two different worlds, we must pre-define any data that must pass between the two using a special language called "Interface Definition Language" - a C like language where we will define structs, constructors, etc for this data and follow it up with matching C++ code.
