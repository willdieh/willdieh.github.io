## Observable Bindings

In XAML and winrt, an *observable* binding is one that reflects changes in the UI whenever the underlying value is modified in code. 

Let's update our MenuBar click-handler functions to set a different value for `m_MyProperty` whenever we change the layout in the View menu

**`MainWindow.xaml.cpp`**
```c++
...
using namespace winrt::Microsoft::UI::Xaml::Controls;   // For RadioMenuFlyoutItem
...
void MainWindow::OnOrientationClick(IInspectable const& sender, RoutedEventArgs const& e)
{
    // Cast the sender parameter as a RadioMenuFlyoutItem
    auto clickedItem = sender.as<RadioMenuFlyoutItem>();

    // If Cast was successful, check which radio button was clicked
    if (clickedItem)
    {
        if (clickedItem.Text() == L"Portrait")
        {
            m_MyProperty = 1;
        }
        else if (clickedItem.Text() == L"Landscape")
        {
            m_MyProperty = 2;
        }
    }
}
```

If you compile and run the app, you notice there's no change when we toggle the layout in the menu. This is because the simple binding we did in the last post for the `Int32 MyProperty` object was ***not*** observable - the GUI will always display the initial value. So how do we make `MyProperty` *observable*?

## INotifyPropertyChanged

The secret lies with a special cpp/winrt class called `INotifyPropertyChanged`. When you inherit from this class in your `idl` object definition and define some special event registration and de-registration functions in your C++ code, your XAML and C++ code will be able to synchronize values. I won't lie - this part sucks. But it's not too bad if you list the steps and follow them through:

### Add `INotifyPropertyChanged` to your runtime class (`idl` file)

**`MainWindow.idl`**
```idl
namespace WinUIApp
{
    [default_interface]
    runtimeclass MainWindow : Microsoft.UI.Xaml.Window, Microsoft.UI.Xaml.Data.INotifyPropertyChanged
    {
        MainWindow();
        Int32 MyProperty;
    }
}
```
  
This will cause the auto-generated c++ code to re-generate and add the necessary class inheritance to your c++ class behind the scenes. Once you re-compile, you will see the added `INotifyPropertyChanged` stuff if you dig into the `MainWindowT` class from which `MainWindow` inherits. 

### Add required `INotifyPropertyChanged` C++ code

Because we now inherit from `INotifyPropertyChanged` there are some mandatory functions we must define or our compile will fail with errors like `'PropertyChanged': is not a member of 'winrt::WinUIApp::implementation::MainWindow'`. We must also define a local `winrt::event` member we will use to send change events.

**`MainWindow.xaml.h`**
```c++
...
using namespace winrt::Microsoft::UI::Xaml::Data; // For PropertyChangedEventHandler
...
    // Event Handlers for INotifyPropertyChanged registration/de-registration
    winrt::event_token PropertyChanged(PropertyChangedEventHandler const& handler); 
    void PropertyChanged(event_token const& token);

private:
...
    // Property Changed event object
    winrt::event<PropertyChangedEventHandler> m_propertyChanged;

    // Used internally by our Setters to raise a Property Changed Event
    void RaisePropertyChanged(std::wstring_view propertyName); 
```
